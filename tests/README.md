# Tests and benchmarks

Run commands from the repository root. Generated files belong under `build/` or `test-results/`; do not commit personal captures. All added test and tool source follows the whole program's GPL-3.0-or-later terms unless a file states otherwise.

## Default offline regression suite

After the [Release Ninja build](../doc/windows-ucrt-build.md), run in PowerShell:

```powershell
./tests/run_loop_csv_tests.ps1 -ToolchainRoot C:\msys64\ucrt64
./tests/run_snapshot_test.ps1 -ToolchainRoot C:\msys64\ucrt64
```

Use your actual UCRT64 prefix. The recorder runner covers segment boundaries, independent reconstruction, compression corruption, queue overflow, manual-stop tails and the session packet hook. The hook test constructs an uninitialized session; it does not open or capture from a physical device. The snapshot test exercises lifetime and concurrent ownership in memory.

Additional formatter/scanner checks can be built and run in UCRT64:

```sh
mkdir -p build
gcc -O2 -Icommon tests/csv_output_equivalence_test.c libsigrok4DSL/output/csv.c -o build/csv_output_equivalence_test.exe $(pkg-config --cflags --libs glib-2.0 libusb-1.0)
./build/csv_output_equivalence_test.exe
g++ -O2 -std=c++11 tests/logic_csv_edges_test.cpp -o build/logic_csv_edges_test.exe $(pkg-config --cflags --libs Qt5Core)
./build/logic_csv_edges_test.exe
```

The title-bar SVG check requires the resource object generated by the Release build:

```sh
g++ -O2 tests/titlebar_svg_render_test.cpp build/ucrt/CMakeFiles/DSView.dir/qrc_DSView.cpp.obj -o build/titlebar_svg_render_test.exe $(pkg-config --cflags --libs Qt5Widgets)
QT_QPA_PLATFORM=offscreen QT_PLUGIN_PATH=/ucrt64/share/qt5/plugins ./build/titlebar_svg_render_test.exe
```

## Optional recorder benchmarks

These write compressed output and may consume substantial disk space. They are separate from the default suite and do not use a physical device. Compile a recorder benchmark by replacing `BENCHMARK` with one of the source names below:

```sh
g++ -O2 -std=c++11 tests/BENCHMARK.cpp DSView/pv/data/loopcsvrecorder.cpp -o build/BENCHMARK.exe $(pkg-config --cflags --libs Qt5Core) -lzstd
```

| Program | Arguments | Input |
| --- | --- | --- |
| `loop_csv_dense_realtime_test` | `OUTPUT_DIRECTORY [SECONDS [ENCODERS [PATTERN]]]` | Synthetic six-channel 50 MHz data; defaults: 15 s, automatic encoders, pattern 2. Patterns: 1 toggles each sample, 2 each two samples, 3 random words. |
| `loop_csv_capture_file_test` | `INPUT_DIRECTORY OUTPUT_DIRECTORY` | Six equally sized, nonempty `ch0.bin` through `ch5.bin` files; channel data is bit-packed LSB first and each file is a multiple of eight bytes. Uses a fixed 50 MHz rate. |
| `loop_csv_realtime_replay_test` | `INPUT_DIRECTORY OUTPUT_DIRECTORY` | The same six-channel format, replayed four times and paced at 50 MHz. |

Expected sample totals are derived from the supplied channel-file size. No private input files are bundled. The historical reports used an earlier revision of these benchmark CLIs with developer-local paths.

## Application and physical-device harnesses

`export_actual_benchmark INPUT_DSL OUTPUT_DIRECTORY` compares legacy and optimized export using the application session. It initializes the full application, which may enumerate devices; it is not part of the device-free suite. It refuses to replace existing `benchmark-legacy.csv` or `benchmark-fast.csv` output.

`hardware_export_capture_benchmark --run-hardware OUTPUT_DIRECTORY` opens a physical device, changes capture settings and starts two captures. It is opt-in, is not run by either test script, and refuses to replace its existing output files. It is a development harness, not an end-user diagnostic tool. Both application harnesses require the application resources/runtime and linking with the Release application objects excluding `main.cpp`, as the session test runner does; they are not standalone recorder programs.

Historical measurements are linked from the main README. Passing offline tests does not establish real-time USB throughput or device reliability.
